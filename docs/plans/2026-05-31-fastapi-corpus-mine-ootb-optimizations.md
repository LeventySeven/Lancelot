# FastAPI corpus → Lancelot out-of-the-box optimizations

## 1. Executive summary

The corpus mine confirms a sharp, defensible story: **Lancelot already owns the hard parts of the byte path** (the C2 disconnect→upstream-cancel race, the RED+TTFT metric triad, the R3 SSE pump, `@app.batch` coalescing, bounded-pool 503 backpressure, request-id/traceparent propagation, one-pass pydantic-core serialization), and the highest-leverage remaining wins are *finishing patterns Lancelot already half-built* — not new surface. The single biggest gap is that **C2 disconnect-cancellation is wired ONLY to streaming routes** (`asgi.py:659-685` is inside `if getattr(route, "is_stream", False)`), so the marquee "stop paying for unwatched tokens" win silently does not cover the most common shape — a non-streaming `async def` that awaits one LLM call (vLLM's entire `with_cancellation` decorator exists for exactly this). Three observability/composition items are outright **bugs**: metrics are labelled by the *concrete* URL not the route template (`asgi.py:179` → `metrics.py:134`, the unbounded-cardinality trap ludwig fell into), mounted sub-app lifespans **never run** under `serve()` (`asgi.py:101-159` drives only `app._lifespan`), and `operation_id`/`generate_unique_id_function` overrides are dead code (`openapi.py:280` always uses the hardcoded formula). The strongest *new* primitive is an **OpenAI-compat transport shim** (`/v1/chat/completions` + `/v1/models` + `ChatCompletionChunk` SSE framing) — 5/24 inference servers hand-roll it from pieces Lancelot already ships, and assembling it keeps model-resolution user-side. Below, GAPs are deduped across the 12 dimensions (disconnect-cancellation surfaced in 4 separate dimensions; the custom-APIRoute seam in 4; SSE framing in 3) and ranked by recurrence × byte-path fit × not-shipped × low effort.

## 2. Top out-of-the-box optimizations (ranked)

### 1. Extend C2 disconnect→cancel to non-streaming handlers + the public `cancel_on_disconnect` surface
- **Pain:** every project that issues a long LLM/inference call from a *unary* (non-SSE) handler hand-rolls a `create_task(handler) + create_task(listen_for_disconnect) + asyncio.wait(FIRST_COMPLETED) + cancel` race. vLLM ships a whole `with_cancellation` decorator and documents `request.is_disconnected()` is "broken under middleware."
- **Recurrence:** ≥5/24 with explicit machinery (vllm, langflow, modal, ludwig, ray_serve); surfaced as a GAP in **4 separate dimensions** (disconnect, batching, background, middleware).
- **Lancelot evidence (confirmed):** the watcher `_watch_disconnect` and `lreq._cancel_event = asyncio.Event()` are created **only** inside `if getattr(route, "is_stream", False):` (`asgi.py:659-685`). For a plain `@app.get`/`@app.post` (`asgi.py:853-878`) no watcher is spawned and `_cancel_event` stays `None`, so `llm.py:358 _await_cancellable` reads `None` → zero-overhead pass-through → the in-flight upstream is **never** cancelled on disconnect. `requests.py:39-44 cancelled` docstring literally says "mid-stream." Both the dual-task race (`llm.py:361-378`) and the watcher already exist internally — they were just never wired to non-stream routes or exposed.
- **Proposed surface:** factor `_watch_disconnect` out of the is_stream branch; add `@app.get('/x', cancel_on_disconnect=True)` (route kwarg + app default). When set on an async/timeout'd route, spawn the watcher, set `_cancel_event`, and race the handler task vs the disconnect via the existing `_await_cancellable` shape. Add a FastAPI-named `request.is_disconnected()` alias → `self.cancelled` so migrating users find the exact method. Keep the tiny one-shot fast path untouched (only arm for async/timeout'd routes).
- **Where:** `lancelot/asgi.py` (shared `_watch_disconnect` helper + arm on the `853-878` branch), `lancelot/routing.py` (`cancel_on_disconnect` kwarg), `lancelot/requests.py` (alias + docstring generalize).
- **Effort:** 6-9h.
- **Positioning:** pure transport lifecycle — "stop server work + stop paying for upstream tokens the instant the socket closes." The agent loop is untouched.

### 2. Fix the metric label: route TEMPLATE, not concrete URL (cardinality bug)
- **Pain:** labelling metrics by raw path (`/items/42`) blows up Prometheus cardinality; every mature project rediscovers "use the route template."
- **Recurrence:** 5/24 explicitly fix it (sentry, bitcart, dispatch, ray_serve, polar); ludwig gets it **wrong** → 6/24 touch the exact decision.
- **Lancelot evidence (BUG confirmed):** `asgi.py:310 record_request(path, ...)` where `path = scope["path"]` (`asgi.py:179`) — the concrete URL. `metrics.py:134` stores it as `"http.route"`. The matched `Route` (carrying `.path` = template) is resolved at `asgi.py:357` inside `_http_dispatch` but **never threaded back** to the `_http` finally. So Lancelot ships exactly ludwig's unbounded-cardinality trap, and matchit already knows the template for free.
- **Proposed surface:** stash `scope['_lancelot_route'] = route.path` right after the match (`asgi.py:357`); have the `_http` finally read it for `record_request`'s `route_path`. Bounded sentinels for the no-match case: `404 → '__not_found__'`, `405 → '__method_not_allowed__'` (so a URL-spraying scanner can't explode cardinality). `http.status_class='2xx'` already exists (`metrics.py:136`).
- **Where:** `lancelot/asgi.py` (stash + read), `lancelot/metrics.py` (sentinel doc).
- **Effort:** 2-3h.
- **Positioning:** the router owns the template; bounding label cardinality is transport hygiene — the loudest observability lesson in the corpus, fixed for ~zero work.

### 3. Run mounted sub-app lifespans (latent correctness bug) + `root_path` propagation
- **Pain:** mounted FastAPI/Starlette sub-apps each own their own lifespan/docs; the corpus knows mounted-sub-app lifespans are a footgun that "don't always run," and several hand-roll a `LifespanManager`.
- **Recurrence:** `app.mount`/`host` in 8/24; per-worker app-copy + nested-lifespan verified in litserve, ray_serve, modal, bentoml.
- **Lancelot evidence (BUG confirmed):** the dispatcher (`asgi.py:79-89`) delegates http/websocket to `_mounts` but the `lifespan` branch (`asgi.py:101-159`) drives **only** `app._lifespan` — a mounted sub-app's startup/shutdown **never runs** under `serve()`. `mount()` (`app.py:102-106`) just appends `(prefix, app)`. And `asgi.py:84-88` strips the prefix but never sets `sub_scope['root_path']`, so a mounted sub-app emits wrong absolute URLs (its `/openapi.json` server URL, `url_path_for`).
- **Proposed surface:** in `_lifespan`, iterate `_mounts` and enter each mount's lifespan (on the app's AsyncExitStack — see #7) in order, tear down in reverse. Set `sub_scope['root_path'] = mount_prefix` in the dispatcher. Optional `app.host(domain, subapp)` for host-header routing (polar's `app.host(BACKOFFICE_HOST, …)`).
- **Where:** `lancelot/asgi.py` (`_lifespan` + dispatcher root_path), `lancelot/app.py` (`mount` records lifespan-bearing sub-apps; `host`).
- **Effort:** 6-10h (4-6h for the bug-fix half alone).
- **Positioning:** ASGI-composition plumbing; sub-app resources silently never initializing is a real correctness bug, squarely in-lane.

### 4. OpenAI-compatible transport shim (`/v1/chat/completions` + `/v1/models` + `ChatCompletionChunk` SSE)
- **Pain:** every model-serving project rebuilds the OpenAI request/response Pydantic shapes, the `/v1/models` registry-indirection, and the `str | AsyncGenerator → ChatCompletionChunk` SSE adaptation.
- **Recurrence:** 5/24 (hayhooks, vllm, letta, litserve, bentoml) — the dominant inference-server archetype, Lancelot's exact AI/cloud audience.
- **Lancelot evidence (confirmed absent):** grep of `lancelot/` + `src/` for `chat_completions`, `ChatCompletionChunk`, `/v1/models`, `openai_compat`, `[DONE]` returns **nothing**. The pieces all exist — `responses.py StreamingResponse`, the R3 pump (`src/stream.rs`), `pool.py offload`, the C2 watcher — but are not assembled.
- **Proposed surface:** `lancelot.openai_compat.mount_openai(app, *, list_models, run, path_prefix='/v1')`. User supplies two callbacks (`list_models() -> list[str]`, `run(model, messages, **opts) -> str | AsyncGenerator[str]`); Lancelot registers the route shapes, does the registry lookup (404 on unknown model), threadpool-offloads a sync `run`, and frames the output as `ChatCompletionChunk` SSE on the R3 pump (collect-if-non-streaming, wrap-string-into-one-chunk + `data: [DONE]\n\n` if streaming). Model resolution + token generation stay 100% user-side.
- **Where:** new `lancelot/openai_compat.py` composing `lancelot/stream.py`, `lancelot/responses.py`, `lancelot/pool.py`, and the #1 disconnect watcher.
- **Effort:** 8-12h.
- **Positioning:** OpenAI wire shapes + chunk SSE framing are pure serialization/streaming (the marquee); the upstream call stays user-side, exactly like `@app.batch`.

### 5. SSE-of-models framing + `done_sentinel='[DONE]'` (the universal SSE wire format)
- **Pain:** 7/24 hand-roll the identical OpenAI SSE wire: `model_dump_json()` → `yield f"data: {...}\n\n"` → `data: [DONE]\n\n`. 18/24 contain literal `data:` framing.
- **Recurrence:** 7/24 (vllm, litserve, letta, r2r, langflow, polar, bentoml); surfaced in 2 dimensions (SSE + serialization).
- **Lancelot evidence (PARTIAL):** `stream.py Event.render()` owns `event:`/`data:` framing with CR/LF/NUL scrubbing (`stream.py:15-40`), and `_stream_chunk_bytes`/`src/stream.rs:48-75` coerce bytes/str/Event. **But** a yielded bare Pydantic model gets newline-delimited JSON, **not** `data: <json>\n\n` (wrong shape for an OpenAI client), and there is **no** `[DONE]` sentinel anywhere (grep confirms zero `[DONE]` in `lancelot/`).
- **Proposed surface:** `@app.stream(sse=True, done_sentinel='[DONE]')` (or `lancelot.stream.sse(model)` helper) so a yielded model/dict is framed `data: <pydantic-core json>\n\n` via `serialize::to_json_bytes` (not Python `model_dump_json`), and the framework auto-emits `data: [DONE]\n\n` on generator exhaustion. Event/bytes/str paths unchanged (backward compatible). This is the framing half that #4 reuses.
- **Where:** `lancelot/stream.py`, `lancelot/asgi.py` (`_stream_chunk_bytes` + EOF sentinel in the is_stream loop), `src/stream.rs` (mirror coercion + EOF), `lancelot/routing.py`/`lancelot/app.py` (kwargs).
- **Effort:** 5-8h.
- **Positioning:** SSE wire framing + Rust-core per-chunk serialization; the token-producing generator stays user-side.

### 6. App-lifetime resource tier + structured lifespan + supervised lifetime tasks
- **Pain:** every inference server injects the engine/model via `app.state` through a spanning lifespan with a hand-rolled None-guard accessor, hand-writes the ordered-acquire/reverse-dispose ladder, and re-codes `create_task + strong-ref + done-callback + cancel + wait_for + suppress(CancelledError)` for a supervising daemon.
- **Recurrence:** app.state injection 6/24; `lifespan=` 9/24; supervising-task shape verified in 5 (vllm, litserve, opal, bitcart, letta). Three sub-patterns that merge into one registry.
- **Lancelot evidence (confirmed):** `app.py:9-22 State` is an untyped bag; `di.py` scope is only `'function'|'request'` (no app tier); `docs/agents.md` literally tells users to hand-roll `app.state.client = httpx.AsyncClient()`. `_lifespan` enters `app._lifespan` as **one** unit (`asgi.py:125-159`) — no AsyncExitStack registry, no reverse teardown. `background.py spawn` is detached fire-and-forget, not a lifecycle-bound supervised daemon. No `app.resource`/`app.lifetime_task`/`add_lifecycle` exists.
- **Proposed surface:** (a) `app.resource('engine', factory)` — singleton built once at startup, injected at compile-bound time (reuse `di._bind_req_params` magic-injectable machinery, no per-request None-guard; absence = startup error). (b) `app.add_lifecycle(name, setup=, teardown=)` entered on an internal AsyncExitStack with LIFO reverse teardown + partial-startup safety (the AsyncExitStack guarantee `di.solve_async` already uses). (c) `app.lifetime_task(coro_fn)` — started at startup, strong-ref retained, cancelled + awaited (bounded by `LANCELOT_DRAIN_SECS`) in `drain()`. All three compose; plain `lifespan=` stays supported. This is the shared AsyncExitStack that #3's mount-lifespan chaining and #9's `on_commit` flush hang off.
- **Where:** `lancelot/app.py` (registries + app-owned AsyncExitStack; extend `drain()` at `585-599` to cancel registered tasks), `lancelot/di.py` (new bind kind), `lancelot/asgi.py` (`_lifespan` builds resources + starts tasks at startup).
- **Effort:** 12-18h combined (resource tier 8-12, lifecycle ladder 6-10, lifetime task 5-8 — overlapping).
- **Positioning:** operator-experience/resilience — the inject-and-read + ordered-teardown + bounded-cancel plumbing every inference server rebuilds; the engine/coro are the user's, Lancelot owns the typed singleton seam + bounded teardown (consistent with B1 graceful drain).

### 7. Structured error envelope + retry-taxonomy helper
- **Pain:** 11/24 register custom exception handlers or a base-endpoint envelope; letta has **49** `add_exception_handler` calls; polar ships a `PolarError` hierarchy with `.schema()`. Each re-codes the same `{error:{type,message,detail}}` + status map.
- **Recurrence:** 11/24.
- **Lancelot evidence (PARTIAL):** the hooks exist — `app.py:560-575 add_exception_handler`/`@app.exception_handler`, `asgi.py:1323 _find_exc_handler` MRO-walk, `HTTPException`/`RequestValidationError`, `metrics.py` puts `http.status_code` on every metric, `responses.py:86 set_retry_hint → X-Should-Retry`. **Missing:** grep for `problem+json`/`RFC.9457`/`ProblemDetail`/`error_envelope` returns **nothing**. Lancelot gives only the raw hook + a bare `HTTPException(status, detail)` emitting `{"detail": ...}` (`asgi.py:1185`).
- **Proposed surface:** an opt-in structured-error envelope (e.g. `App(error_envelope=...)` or a `lancelot.exceptions.ProblemDetail` helper) that shapes `{error:{type,message,...}}` consistently and folds the existing `set_retry_hint`/Retry-After into the taxonomy. Optionally route the mid-stream SSE error frame (`asgi.py:790-818`) through `_find_exc_handler` so a registered handler can shape it (it currently hard-codes a constant — which is the *safe* default, so this is low-priority polish).
- **Where:** `lancelot/exceptions.py` (envelope helper) + `lancelot/asgi.py` (wire into the HTTPException emit + optional stream-error hook).
- **Effort:** 4-6h.
- **Positioning:** byte path — it is the canonical error JSON bytes + the Retry-After/X-Should-Retry wire + the status that feeds the existing RED metric. A typed exception class, not a domain model.

### 8. Live route add/remove with const-tier eviction + OpenAPI cache-bust
- **Pain:** the inference-server archetype adds/removes a `/pipeline/run` route at runtime and busts the OpenAPI cache by hand (`app.routes.remove(r)` + `app.openapi_schema=None; app.setup()`).
- **Recurrence:** 6/24 (hayhooks, litserve, prefect, bitcart, modal, ludwig); surfaced in 2 dimensions.
- **Lancelot evidence (GAP + a Lancelot-specific hazard):** no `remove_route`/`add_route_dynamic` exists. Two coherence hazards a hand-rolled `app.routes.remove()` would MISS: (1) the Router keeps a **separate** `_const`/`_const_paths`/`_dyn` (`routing.py:637-668`) — removing from `.routes` alone leaves a stale const-tier O(1) hit serving the dead route; (2) the OpenAPI cache is memoized once with no invalidation (`app.py:528-538`, docstring: "built once"). And `src/router.rs add()` only **inserts** (matchit `.insert` returns Conflict on dup; no delete) — so the Rust router needs a remove/rebuild path.
- **Proposed surface:** `App.add_route_live(...)` / `App.remove_route(path, method=None)` (+ `Router.remove`) that evict from **both** tiers (`_const`/`_const_paths`/`_dyn`) AND `routes`, null `_openapi_cache`, and update the Rust matchit router (rebuild the method tree on remove, since matchit has no delete).
- **Where:** `lancelot/routing.py` (`Router.remove` + tier eviction), `lancelot/app.py` (the methods + cache bust), `src/router.rs` (remove/rebuild).
- **Effort:** 6-10h (Python ~4h, Rust matchit rebuild ~3-5h).
- **Positioning:** routing-table + cache surgery the framework must own; const-tier eviction is the value FastAPI can't give. Lower priority — ship when an inference-server user asks.

### 9. `@app.batch` adaptive/budget knobs (size_fn + window snapshot + defer-to-tail)
- **Pain:** fixed-window count-based coalescing can't size by token/byte budget; ray_serve caches the window at batch-open and defers an over-budget item to the next batch; bentoml learns batch latency online and sheds the head past its SLA.
- **Recurrence:** the coalescer itself recurs 4/24 (litserve, bentoml, ray_serve, modal); the budget/adaptive knobs from ray_serve + bentoml.
- **Lancelot evidence (confirmed):** `batch.py:57` reads `self.max_batch` **live** each submit and only compares `len(self.pending)`; `app.py:279-280` signature is `batch_window_ms`/`max_batch`/`max_keys`/`key` only — no `size_fn`, no per-batch window snapshot, no `max_latency`. `batch.py:68` is a fixed `asyncio.sleep(window_s)`.
- **Proposed surface:** (1) snapshot `window_s`+`max_batch` into `_BatchGroup` at first-submit so a future live retune can't corrupt a half-built batch; (2) `size_fn=lambda items: sum(...)` so the flush trigger is a byte/token **budget** not a count; (3) defer an over-budget item to the next batch instead of overflowing. (Adaptive `max_latency_ms` learned-hold is a larger, lower-priority follow-on — `metrics.py` already records per-request duration, so the sample source exists.) `size_fn` is user-supplied, so no tokenizer ships.
- **Where:** `lancelot/batch.py` (`_BatchGroup.submit` + `_run_batch`), `lancelot/app.py:279` kwargs.
- **Effort:** 4-6h (budget knobs); +10-14h if the adaptive SLA-hold is pursued separately.
- **Positioning:** request-scheduling/coalescing-budget math on the transport seam — the framework owns *when to fire*; the upstream call stays user-side.

### 10. WebSocket parity: ContextVar/traceparent seam + handshake-auth + `@app.middleware('websocket')`
- **Pain:** WS connections fall outside Depends/middleware in Starlette, so projects re-plumb DI via raw ASGI; handshake auth is hand-rolled (query/cookie/header → close 1008/4001).
- **Recurrence:** 4/24 special-case `scope['type']=='websocket'` (bitcart, polar, modal, vllm); 4/24 hand-roll handshake auth (opal, bitcart, langflow, prefect).
- **Lancelot evidence (GAP confirmed):** `middleware.py` adapters pass WS scopes through untouched; `app.py middleware(kind='http')` is the only kind. `_ws` (`asgi.py:1248-1320`) **never sets any ContextVar** — request_id/trace_id/agent_id are set only in `_http`. So a WS connection gets no request-id echo, no traceparent propagation, and `@app.middleware('http')` never runs. (The handshake *does* run `solve_async`, so Depends resolves — the gap is the ContextVar/trace seam + a declarative auth surface + a WS middleware kind.)
- **Proposed surface:** (1) factor the `_http` header-scan (`asgi.py:216-237`) into a shared helper; call it from `_ws` to set request_id + traceparent + agent_id inside try/finally (so `TransportPool._inject_traceparent` forwards the socket's trace to upstream calls automatically). (2) Add `@app.middleware('websocket')` + a `WSMiddlewareAdapter` for per-socket resource deps. (3) A declarative handshake-auth seam (`QueryToken`/`WSCookie`/`WSHeader` + named close-code constants) that closes with the correct code **before** the handler runs.
- **Where:** `lancelot/asgi.py:_ws` (shared header/ContextVar helper), `lancelot/middleware.py` (`WSMiddlewareAdapter`), `lancelot/app.py:middleware` (accept `'websocket'`), `lancelot/websockets.py`/`lancelot/security.py` (auth sources + close codes).
- **Effort:** 7-11h (the ContextVar/trace + middleware-kind half is the in-lane core; full auth seam adds to it).
- **Positioning:** observability/lifecycle symmetry — request-id echo + traceparent propagation are transport plumbing Lancelot already ships for HTTP; extending the same machinery to WS closes the parallel-paths gap. (WS pub/sub broadcast and the WS↔upstream bridge are larger, separately-justified builds — see the load-gate.)

### 11. `operation_id` / `generate_unique_id_function` / `openapi_extra` (SDK-codegen method names)
- **Pain:** the official FastAPI full-stack template ships `generate_unique_id_function`; polar uses `operation_id` + 7 Speakeasy mixins stamping `openapi_extra`. The operationId IS the generated SDK/MCP method name.
- **Recurrence:** 2/24 — but one is the *official template*, so high credibility for the SDK/code-gen audience.
- **Lancelot evidence (GAP confirmed empirically):** `openapi.py:280` always calls the hardcoded `operation_id(r)`; `route.operation_id` is stored (`routing.py:65`) but **never consumed**; `generate_unique_id_function` exists only in the `app.py:38` docstring. Probe: `@app.get('/checkouts', operation_id='checkouts:create')` emitted `create_checkout_checkouts_get` (the formula), not the override. `openapi_extra` has nowhere to land in `build_openapi`.
- **Proposed surface:** in `build_openapi`, before the formula fallback: use `r.operation_id` verbatim if set, else `app._generate_unique_id_function(r)` if set, else the formula. Capture the factory in `App.__init__` (currently swallowed into `_extra_kwargs`). Add `openapi_extra: dict | None` as a Route field, shallow-merged into the per-path op dict. The OpenAPI cache is memoized, so this is build-time only — zero hot-path cost.
- **Where:** `lancelot/openapi.py` (build_openapi + operation_id), `lancelot/app.py` (capture factory), `lancelot/routing.py` (openapi_extra field).
- **Effort:** 3-4h.
- **Positioning:** pure OpenAPI-generation — the operationId is the generated SDK/MCP method name, directly the AI/SDK-codegen audience. It's what bytes go into `/openapi.json`.

### 12. Detached `background.spawn` loses request context (one-line consistency fix)
- **Pain:** the dispatch `organization_slug` dance — a truly-detached task that outlives the response loses request-scoped state, so the user hand-threads correlation ids.
- **Recurrence:** subset of 6-7/24 (dispatch incident flow, long audit emit).
- **Lancelot evidence (GAP + inconsistency confirmed):** `background.py:58-66 _run` submits to a raw `ThreadPoolExecutor` with **no** `contextvars.copy_context()` — unlike `pool.py` offload/run_backpressured which both copy_context. So a detached `spawn()` runs in an empty context: request_id/trace_id/tenant_id all read their `'-'` sentinels. The asymmetry (offload propagates, spawn doesn't) is itself a latent surprise.
- **Proposed surface:** capture `ctx = contextvars.copy_context()` at `spawn()`-time and run via `ctx.run(fn, ...)` (one-line, mirrors `pool.py:48`). The detached task then carries request_id + traceparent + tenant_id into its logs/metrics/outbound calls automatically. Keep refusing durability/retry (user's queue).
- **Where:** `lancelot/background.py` (`BackgroundPool.spawn` + module `spawn`).
- **Effort:** 2-3h.
- **Positioning:** pure context propagation — Lancelot already owns these ContextVars; propagating them into its own detached pool is byte-path.
